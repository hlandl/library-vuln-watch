Fix tracks `HttpEndpointModel` by consumer reference; commit message uses "Harden" colloquially for a follow-up review-feedback commit (`LinkedHashSet` instead of `TreeSet`, null-consumer guards) — reviewed the full diff and this is an availability/correctness fix for route-stop endpoint bookkeeping, not a new attack-surface or auth/validation change. `camel-platform-http`(-vertx) is not a `used_component`. `NOT-SECURITY` / `NOT-USED`.
- **CAMEL-24614** — `camel-langchain4j-agent`: producer threw an opaque `NullPointerException` instead of a clear `IllegalArgumentException` when no agent/agentFactory could be resolved. Pure error-message/diagnostics fix. `camel-langchain4j-agent` is not a `used_component`. `NOT-SECURITY` / `NOT-USED`.
- **CAMEL-24571** — `camel-spiffe`: new `SpiffeSSLContextParameters` for SPIFFE Workload-API-backed mTLS. This is a **new feature** (adds mTLS support), not a fix to an existing vulnerability; keyword grep flagged it only on the mundane "SSL"/"TLS" substrings in the feature description. `camel-spiffe` is not a `used_component`. `NOT-SECURITY` / `NOT-USED`.
- **CAMEL-24560** — `GenAiUsage`: widen `inputTokens`/`outputTokens` from `Integer` to `Long` to avoid lossy casts/`Math.toIntExact` failures on large token counts from OpenAI and other providers. Type-correctness fix, no trust boundary involved. Not a `used_component` (GenAI usage tracking). `NOT-SECURITY` / `NOT-USED`.
