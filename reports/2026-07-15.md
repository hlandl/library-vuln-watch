## Findings

### CVE-2026-33454 / GHSA-2vqf-x7g4-7c2g — Camel-Mail message header injection
- **Is this a vulnerability?** CONFIRMED — published CVE, CVSS 9.4 (Critical).
- **Affected range vs. our version:** Advisory lists `org.apache.camel:camel-mail` affected
  `3.0.0 – <4.14.6` and `4.15.0 – <4.18.1`, patched in 4.14.6 / 4.18.1. Our pinned **4.8.8**
  falls inside the first range → **AFFECTED**.
- **Component in use?** `camel-mail` is in `used_components` → **USED**.
- **Verdict: AFFECTS US.**
- **Description:** `MailHeaderFilterStrategy` only filtered *outbound* Camel-prefixed
  headers (`setOutFilterStartsWith`), never inbound ones. An attacker who can deliver an
  email into a monitored mailbox can inject `Camel*`-prefixed MIME headers that survive
  into the Exchange and influence downstream header-driven components (e.g. `camel-bean`,
  `camel-exec`, `camel-sql`).
- **Sources:**
  - Advisory: https://github.com/advisories/GHSA-2vqf-x7g4-7c2g
  - Jira: https://issues.apache.org/jira/browse/CAMEL-23222 *(link only — Apache Jira was
    unreachable this run, not independently verified)*
  - Fix commit: https://github.com/apache/camel/commit/540d48e
  - Related commits mentioned in the advisory: `0307dd4`, `05cffa5`, `3926ab2`, `5c20de8`, `e074c01`
- **Official fix:** Single-line fix in
  `components/camel-mail/src/main/java/org/apache/camel/component/mail/MailHeaderFilterStrategy.java`:
  ```diff
       setOutFilterStartsWith(CAMEL_FILTER_STARTS_WITH);
  +    setInFilterStartsWith(CAMEL_FILTER_STARTS_WITH);
  ```
  First shipped in 4.14.6 (and 4.18.1 on the other maintenance line).
- **Backport assessment:** Confirmed clean. Fetched
  `MailHeaderFilterStrategy.java` as it exists at our pinned `camel-4.8.8` tag — it has the
  identical `initialize()` shape (constructor → `setOutFilterStartsWith(...)` only, last
  touched Feb 2021), so the one-line addition applies verbatim with no drift. Recommend also
  porting the regression test added alongside commit `540d48e` (not individually inspected —
  check the camel-4.14.6 diff of `MailHeaderFilterStrategyTest` or equivalent). Two follow-up
  hardening commits landed later on main and are **not required** to close this CVE but are
  worth reviewing for defense-in-depth — see CAMEL-23522 below and the related
  CAMEL-23543 "centralize and harden `Camel*` header filtering in `DefaultHeaderFilterStrategy`"
  refactor (2026-06-12, https://github.com/apache/camel/commit/c2ce026, no CVE attached).

### CVE-2026-47323 / GHSA-8364-hfqj-pwm6 — CXF/Knative inbound header injection
- **Is this a vulnerability?** CONFIRMED — published CVE, CVSS 9.8 (Critical).
- **Affected range vs. our version:** The advisory's structured "affected packages" field
  names only `org.apache.camel:camel-cxf-rest` (`>=3.18.0, <4.14.6` / `>=4.15.0, <4.18.2`,
  patched 4.14.6 / 4.18.2), which is **not** in our `used_components` — on the advisory
  metadata alone this would be NOT RELEVANT. **However**, the actual fix commit
  (`7ce327d`, PR #22413, "Add inbound header filtering to CXF and Knative filter
  strategies") touches three files, not one:
  - `camel-cxf-rest/.../CxfRsHeaderFilterStrategy.java`
  - `camel-cxf-transport/.../CxfHeaderFilterStrategy.java` ← **this is in our `used_components`**
  - `camel-knative-http/.../KnativeHttpHeaderFilterStrategy.java`
  All three get the identical one-line `setInFilterStartsWith(CAMEL_FILTER_STARTS_WITH)`
  (or equivalent pattern) addition. `camel-cxf-transport`'s header filter class is shared by
  the SOAP binding (`camel-cxf-soap`, `camel-cxf-spring-soap`, also in our `used_components`),
  so the same unauthenticated-header-injection issue applies to our CXF-SOAP usage too, not
  just REST. **The advisory's affected-package list appears incomplete for this CVE.**
- **Component in use?** `camel-cxf-transport` → **USED**. `camel-cxf-rest` itself → not used.
- **Verdict: AFFECTS US** (via `camel-cxf-transport`, on the strength of the actual diff,
  overriding the narrower advisory metadata).
- **Description:** An unauthenticated attacker can inject Camel-internal headers (e.g.
  `CamelExecCommandExecutable`, `CamelFileName`) via HTTP requests to CXF-SOAP/REST
  endpoints; if the route forwards to a header-driven component, this can enable RCE or
  arbitrary file writes.
- **Sources:**
  - Advisory: https://github.com/advisories/GHSA-8364-hfqj-pwm6
  - NVD reference (unreachable, link only): https://nvd.nist.gov/vuln/detail/CVE-2026-47323
  - Official advisory (unreachable, link only): https://camel.apache.org/security/CVE-2026-47323.html
  - Fix commit: https://github.com/apache/camel/commit/7ce327d9147ea4a8f8844982da9b5547f21e0135
  - PR: https://github.com/apache/camel/pull/22413 (backports: #22414 to 4.18.x, #22415 to 4.14.x)
- **Official fix:**
  ```diff
       setOutFilterStartsWith(CAMEL_FILTER_STARTS_WITH);
  +    setInFilterStartsWith(CAMEL_FILTER_STARTS_WITH);
  ```
  applied identically in `CxfHeaderFilterStrategy.java` (camel-cxf-transport), plus the
  REST and Knative classes. First shipped in 4.14.6 / 4.18.2.
- **Backport assessment:** Likely clean — confirmed `CxfHeaderFilterStrategy.java` exists
  at the `camel-4.8.8` tag with the same `initialize()` / `setOutFilterStartsWith(...)`
  shape the patch targets. Recommend backporting the fix to `camel-cxf-transport` (covers
  both our SOAP and transport usage) and porting whatever regression test PR #22413 added.
  **Given the metadata gap, recommend a human re-check the official
  `camel.apache.org/security/CVE-2026-47323.html` page directly (this agent could not reach
  it) to confirm the complete affected-package list before scoping the backport.**

### CAMEL-23522 — camel-mail JavaMail session-property header injection (no CVE/GHSA yet)
- **Is this a vulnerability?** SUSPECTED — the commit message itself calls it a security
  fix ("gating JavaMail session properties from headers... prevents untrusted producers from
  injecting transport-security settings through message headers"), but no CVE or GHSA has
  been published for it as of this run.
- **Affected range vs. our version:** Landed on `main` 2026-05-20 (commit `1e31abc`), after
  our pinned 4.8.8 (tagged 2025-06-21) — **AFFECTED** (pinned version predates the fix and
  has no equivalent gating).
- **Component in use?** `camel-mail` → **USED**.
- **Verdict: NEEDS REVIEW** (real code change, security-motivated, but unconfirmed by an
  official CVE/advisory, so severity is an estimate).
- **Description:** Adds an opt-in `useJavaMailSessionPropertiesFromHeaders` flag (default
  `false`) to `MailConfiguration`; when disabled, `mail.smtp.*`/`mail.smtps.*` properties can
  no longer be set via message headers, and `MailHeaderFilterStrategy` filters those
  header names on the inbound path as defense-in-depth. Related to the same header-injection
  family as CVE-2025-27636/CVE-2025-29891 and CVE-2026-33454, but is a distinct change.
- **Severity:** Medium *(estimated — no CVSS published; requires ability to inject headers
  into an inbound mail exchange, similar precondition to CVE-2026-33454, but impact here is
  limited to mail-transport session properties rather than arbitrary header override)*.
- **Sources:**
  - Commit: https://github.com/apache/camel/commit/1e31abc
  - Referenced in commit message: CAMEL-23522, CVE-2025-27636, GHSA-2c2h-2855-mf97, CAMEL-23222
  - Related follow-up: CAMEL-23543 centralization, https://github.com/apache/camel/commit/c2ce026 (2026-06-12, no CVE)
- **Official fix:** 29 files changed on `main`; core changes in `MailConfiguration.java`,
  `MailProducer.java`, `MailHeaderFilterStrategy.java`, plus generated component docs
  (imap/imaps/pop3/pop3s/smtp/smtps `.json`). No tagged release could be confirmed to
  contain this commit as of this run (not found in the 4.14.6/4.18.x release lines checked).
- **Backport assessment:** Not yet applicable — recommend re-checking on a future run once
  this ships in a tagged release and (if) a CVE/GHSA is published, since the change is
  behavioural (new opt-in default) rather than a one-line patch, and may need adaptation to
  4.8.8's mail component structure.
