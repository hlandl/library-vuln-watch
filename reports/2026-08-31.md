A configurability/reliability improvement, not a fix for a vulnerability. `camel-openai` is **not** a `used_component`. [apache/camel@f7cfe6971](https://github.com/apache/camel/commit/f7cfe6971335e11c68139fc8683125f6365f5d25).
- **CAMEL-24537** — `camel-openai`: `OpenAIProducer` now null-checks the resolved `model` before calling the SDK builder, turning an opaque `NullPointerException` into a clear validation error. `NOT-SECURITY`; component not used. [apache/camel@9fbb4b397](https://github.com/apache/camel/commit/9fbb4b3970d8d5c024e20943be5c76f7173cec6e).
- **CAMEL-24525** — `camel-google-firestore`: bounds the previously-unbounded realtime-change buffer in `GoogleFirestoreConsumer` (a listener callback thread could grow the buffer without limit if the route drained slower than the collection changed). This is a DoS-shaped fix (CWE-400-adjacent), but `camel-google-firestore` is **not** a `used_component`. [apache/camel@66d37e8b3](https://github.com/apache/camel/commit/66d37e8b3887314331d7c853d37142757f9eaa18).
- **CAMEL-24561** — Adds optional Micrometer `Observation` support for GenAI operations (`camel-ai-observability`), falling back to existing OTel span/timer behavior when unavailable. Feature addition, `NOT-SECURITY`; component not used. [apache/camel@084816b0f](https://github.com/apache/camel/commit/084816b0fc00a25baf27ec218a7c5c45d7a395dd) (PR [#25882](https://github.com/apache/camel/pull/25882)).
- **CAMEL-24344/CAMEL-24345** — documentation-only commit adding 4.18.5 upgrade-guide notes for already-backported `camel-google` fixes (raw-format change, `jsonMode` option). No code change in this commit; `camel-google` is not a `used_component`. [apache/camel@c99ab9270](https://github.com/apache/camel/commit/c99ab927083859b37beee5de1673d6f5bad02f50) (PR [#25894](https://github.com/apache/camel/pull/25894)).
- **CAMEL-24438** — `camel-platform-http-main`: worth flagging even though not used. `MainHttpServer.setupStatic()` previously resolved a static-file request against the process working directory first and only fell back to the configured `staticSourceDir` for files the working directory lacked, with **no containment check at all** on the `staticSourceDir` fallback path (`new File(staticSourceDir, u)` with no canonicalisation/prefix check). This is a classic path-traversal shape (CWE-22): a request path such as `../../etc/passwd` could resolve outside the configured directory. The fix adds `MainHttpServer.containedIn(dir, path)`, which canonicalises both the configured root and the candidate path and requires the candidate to stay under the root, refusing (returning `null`/404) otherwise; `security-model.adoc` was updated to document that classpath/working-directory serving is this feature's intended (development-oriented) contract, and that a report is in scope only when the feature serves outside its own configured directory — which is exactly what this fix closes. No CVE/GHSA has been assigned to this fix as of this run. **Component analysis: `camel-platform-http-main` is not in `used_components`** (distinct from `camel-http-base`/`camel-http-common`, which are) → **NOT RELEVANT** under the configured component filter, despite the underlying issue being real and security-relevant. [apache/camel@ac39e99eb](https://github.com/apache/camel/commit/ac39e99eb017ea6221e439861cd341efeae938b3) (PR [#25847](https://github.com/apache/camel/pull/25847)).

All 23 remaining non-ticketed commits in the window (SBOM/catalog regen, dependency bumps incl. `spring-security-core`/`securityhub` SDK version bumps — packaging metadata only, not our dependency graph, and no advisory attached to either bump — CSimple-language removal, flaky-test fixes, doc/build chores) were grep'd for the standard security-keyword set (`CVE`, `security`, `vulnerab`, `CWE`, `exploit`) with matches individually reviewed; none indicated a new vulnerability.
