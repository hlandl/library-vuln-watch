## Findings

### CAMEL-24360 — `camel-undertow`: endpoint default overwrote the binding's undertow-specific header filter
- **Verdict: NOT RELEVANT** — `camel-undertow` is **not** in `config/libraries.yaml`'s `used_components` for `apache-camel` → `NOT_USED`, which drops the finding regardless of affected-range status. Severity: **MEDIUM** *(estimated)* — flagged as a **SUSPECTED** "silent fix" from the `github_repo` commit sweep (no CVE/GHSA exists for it yet).
- **Vulnerability:** `SUSPECTED`. `UndertowEndpoint` defaulted its `headerFilterStrategy` field to a plain `HttpHeaderFilterStrategy`, then pushed that field into the lazily-created `DefaultUndertowHttpBinding` — overwriting the `UndertowHeaderFilterStrategy` the binding's own constructor had already installed. Net effect: on any endpoint-configured (non-Rest-DSL) undertow route, the undertow-specific filtering added in CAMEL-23588 (`websocket.*`-prefix header filtering + `HttpString` header-name validation) was inert. Rest DSL consumers were unaffected (`UndertowComponent` assigns `UndertowRestHeaderFilterStrategy` separately). This is the same *class* of bug as **CVE-2025-30177** (`camel-undertow` header injection, in/out-direction filter bug, fixed in 4.8.6/4.10.3 — already recorded `NOT_RELEVANT` in `state/seen.json` since our pinned 4.8.8 postdates the fix) and **CVE-2026-33454** (`camel-mail` header injection, tracked 2026-07-15), but is a distinct code path — endpoint/binding wiring, not the in/out direction logic.
- **Affected range vs. our version:** Unreleased — only on `main` as of 2026-08-06 (commit `859e93b`, PR #25367), targeting the `4.22.0` upgrade guide. Not verified against the `camel-4.8.8` tag directly, since the component isn't in use regardless (see below) — no point spending the drift-comparison effort step 5 calls for.
- **Component analysis:** `camel-undertow` is **absent** from `used_components` in `config/libraries.yaml` → `NOT_USED` → **NOT RELEVANT**, independent of whether 4.8.8 has the same wiring bug.
- **Sources:**
  - Commit: https://github.com/apache/camel/commit/859e93b4b37fe41918c50812cb1fedb20ca6b8e1
  - Jira: https://issues.apache.org/jira/browse/CAMEL-24360
  - PR: https://github.com/apache/camel/pull/25367
- **Official fix + backport assessment:** Not performed — per methodology, step 5 (fix location + backport assessment) is only done for `AFFECTS US` or high-severity `NEEDS REVIEW` findings; this is neither, since the component is not deployed.
