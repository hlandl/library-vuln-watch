## Findings

### CAMEL-22114 — Fix PQC KeyStore tests on Java 25 (InvalidKeyException)

- **Is this a vulnerability?** `NOT-SECURITY`. On JDK 25+, the JKS KeyStore deserialises ML-DSA
  (post-quantum) keys as JDK-native key objects that Bouncy Castle's `Signature` SPI does not
  recognise, throwing `InvalidKeyException` when signing/verifying. The fix re-encodes keys
  through BC's `KeyFactory` after loading from a KeyStore, transparently converting JDK-native PQC
  keys into BC-compatible ones (a no-op for keys that are already BC instances). This is a
  functional Java-version compatibility fix (an exception being thrown, breaking correct usage on
  JDK 25), not a security weakness being closed — no access-control, injection, or deserialization
  issue is involved.
- **Source / evidence:**
  - Commit: [apache/camel@f7d40785a](https://github.com/apache/camel/commit/f7d40785a7ae885857b75ce8f8f769c99b856cd1)
    ("CAMEL-22114: Fix PQC KeyStore tests on Java 25 (InvalidKeyException) (#25510)"), merged
    2026-08-23. Touches `camel-pqc`'s `PQCProducer.java` (+65 lines, key re-encoding logic) and adds
    a new JDK-25-gated regression test.
  - No GHSA/CVE exists for this ticket (WebSearch and GitHub advisories page checked — nothing
    newer than the entries already in `state/seen.json`).
- **Component check:** `camel-pqc` (and `camel-crypto`) are not in `used_components` in
  `config/libraries.yaml` — moot regardless of the NOT-SECURITY classification.
- **Verdict: NOT RELEVANT** (dropped: not a vulnerability).
