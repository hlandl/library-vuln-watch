## Findings

### CAMEL-23321 — alias of CVE-2026-40860 (camel-jms/camel-sjms unguarded `ObjectMessage` deserialization)
- **Is this a vulnerability?** `CONFIRMED`. This is the underlying Apache Jira ticket for `CVE-2026-40860` (`JmsBinding.extractBodyFromJms()` in camel-jms deserializes inbound `ObjectMessage` payloads with no `ObjectInputFilter`/allow-list/deny-list — RCE via a crafted `ObjectMessage` if a gadget chain is on the classpath).
- **Affected range vs. our version:** 3.0.0–4.14.6 / 4.15.0–4.18.1 / 4.19.0–4.19.x → **4.8.8 AFFECTED**. `camel-jms` **is** a `used_component`.
- **Verdict: AFFECTS US** — identical finding to `CVE-2026-40860`, already tracked since 2026-07-23 with the same verdict. No new analysis needed; recorded as an alias for dedup completeness.
- Sources: [issues.apache.org/jira/browse/CAMEL-23321](https://issues.apache.org/jira/browse/CAMEL-23321), [oss-security — CVE-2026-40860](https://www.openwall.com/lists/oss-security/2026/04/26/10), [OSV — GHSA-m5vh-3fw5-5wgh](https://osv.dev/vulnerability/GHSA-m5vh-3fw5-5wgh).
- **Official fix / backport assessment:** see `reports/2026-07-23.md` for the full writeup — fixed in 4.14.7/4.18.2/4.20.0 (adds `ObjectInputFilter`), clean no-drift backport to 4.8.8.

### CAMEL-23313 — alias of CVE-2026-40453 (incomplete fix of CVE-2025-27636: non-HTTP `HeaderFilterStrategy` case-variant header injection)
- **Is this a vulnerability?** `CONFIRMED`. Underlying Jira ticket for `CVE-2026-40453`: extends case-insensitive header filtering to `JmsHeaderFilterStrategy`/`SjmsHeaderFilterStrategy`/`CoAPHeaderFilterStrategy`/`GooglePubsubHeaderFilterStrategy`. An attacker with JMS producer access can inject case-variant `Camel*` control headers that reach downstream header-driven components (e.g. `camel-exec`, `camel-file`) for RCE/arbitrary file write.
- **Affected range vs. our version:** covers the same window as `CVE-2025-27636`/`CVE-2026-40453` → **4.8.8 AFFECTED**. `camel-jms` **is** a `used_component`.
- **Verdict: AFFECTS US** — identical finding to `CVE-2026-40453`, already tracked since 2026-08-06 with the same verdict. No new analysis needed; recorded as an alias for dedup completeness.
- Sources: [seclists.org/oss-sec — CVE-2026-40453](https://seclists.org/oss-sec/2026/q2/224), [github.com/oscerd/CVE-2026-40453 (reproducer)](https://github.com/oscerd/CVE-2026-40453), [mail-archive — users@camel.apache.org](http://www.mail-archive.com/users@camel.apache.org/msg69510.html).
- **Official fix / backport assessment:** see `reports/2026-08-06.md` for the full writeup — fixed in 4.14.6/4.18.2/4.20.0.

### CAMEL-23576 — alias of CVE-2026-48206 (camel-jira non-prefixed Exchange headers bypass HTTP header filter)
- **Is this a vulnerability?** `CONFIRMED`. Underlying Jira ticket: renames camel-jira Exchange header constants (`IssueKey` → `CamelJiraIssueKey`, etc.) so they're filtered on the HTTP boundary like every other Camel control header; previously an HTTP client could drive arbitrary Jira issue operations using the endpoint's configured credentials.
- **Component analysis:** `camel-jira` is **not** in `used_components`.
- **Verdict: NOT RELEVANT** (component not used) — identical finding to `CVE-2026-48206`, already tracked since 2026-08-06 as `NOT_RELEVANT`. Recorded as an alias for dedup completeness.
- Sources: [camel.apache.org/security/CVE-2026-48206.html](https://camel.apache.org/security/CVE-2026-48206.html), [seclists.org/oss-sec — CVE-2026-48206](https://seclists.org/oss-sec/2026/q3/47).
- No backport assessment performed (component not used).

### CVE-2026-93494 / CVE-2026-93560 / CVE-2026-93561 / CVE-2026-93563 / CVE-2026-93572 / CVE-2026-93576 / CVE-2026-93578 — Netty codec/TLS batch (published 2026-09-18, product-tagged "Red Hat build of Apache Camel for Spring Boot 4")
- **Is this a vulnerability?** `CONFIRMED` for each (all CWE-1035 "excessive platform resource consumption within a loop", except `-93576` CWE-93 CRLF injection and `-93578` missing-EKU-check revocation bypass). Individually:
  - `CVE-2026-93494`: STOMP frame body missing its terminating null byte → memory leak.
  - `CVE-2026-93560`: STOMP codec content-length `long`→`int` truncation → infinite decode loop (CVSS 7.5).
  - `CVE-2026-93561`: Memcache binary codec signed/unsigned type mismatch → frame desync / response smuggling.
  - `CVE-2026-93563`: `SmtpResponseDecoder` unbounded multi-line accumulation → memory exhaustion (CVSS 7.5).
  - `CVE-2026-93572`: `RedisArrayAggregator` allocates `new ArrayList<>(length)` eagerly per nested RESP array header before validating length against the count of actual child elements → ~12 KB of crafted input can reserve >1 GB of list capacity.
  - `CVE-2026-93576`: `netty-codec-smtp` SMTP command-name field CRLF-sequence validation gap — incomplete fix of `CVE-2025-59419` (CVSS 7.5).
  - `CVE-2026-93578`: OCSP client implementation omits the Extended Key Usage check, allowing acceptance of a certificate that should be treated as revoked (CVSS 5.9).
- **Component analysis:** every one of these is a defect in **Netty's own protocol codecs/TLS handling** (`netty-codec-stomp`, `netty-codec-memcache`, `netty-codec-smtp`, `netty-codec-redis`, `netty-handler`), surfaced under Red Hat's downstream "Red Hat build of Apache Camel for Spring Boot 4" CVE bucket because that product bundles Netty — **not** a defect in any `org.apache.camel`/`camel-*` artifact. Per `config/libraries.yaml`'s explicit scope note, third-party transitive dependencies (Netty included, alongside CXF/MINA/Jackson) are out of scope for this watch and are handled by the regular SBOM/CVE scanning. None of the affected Netty codecs correspond to a `used_component` in any case (no `camel-netty`, `camel-stomp`, or `camel-memcache` in our used-components list; `camel-mail`'s SMTP transport uses `javax.mail`, not `netty-codec-smtp`).
- **Verdict: NOT RELEVANT** for all seven (transitive dependency, out of scope; also no used_component touched even if it were in scope).
- Sources: [radar.offseq.com — CVE-2026-93494](https://radar.offseq.com/threat/cve-2026-93494-cwe-1035-in-red-hat-red-hat-build-of-apache-camel-for-spring-boot-4-3e2dc98e1e118916), [CVE-2026-93560](https://radar.offseq.com/threat/cve-2026-93560-cwe-1035-in-red-hat-red-hat-build-of-apache-camel-for-spring-boot-4-9a86ffee140b81fd), [CVE-2026-93561](https://radar.offseq.com/threat/cve-2026-93561-cwe-1035-in-red-hat-red-hat-build-of-apache-camel-for-spring-boot-4-a3a936e3f67c2b19), [CVE-2026-93563 (TheHackerWire)](https://www.thehackerwire.com/vulnerability/CVE-2026-93563/), [CVE-2026-93572 (strix.ai)](https://www.strix.ai/cve/CVE-2026-93572), [CVE-2026-93576 (offseq)](https://radar.offseq.com/threat/cve-2026-93576-improper-neutralization-of-crlf-sequences-crlf-injection-in-red-hat-red-hat-build-of-089ffa19b51ad43b), [CVE-2026-93578 (strix.ai)](https://www.strix.ai/cve/CVE-2026-93578).
- No backport assessment performed (out of scope, component not used).
