- **Is this a vulnerability?** `CONFIRMED` — a GHSA id now exists for the long-standing `CVE-2013-4330` (CWE-94, code injection via unsanitized `$simple{}` expressions in `CamelFileName` processed by FILE/FTP producers).
- **Does the affected version range include our pinned version?** `NOT-AFFECTED` — GHSA/NVD list the fixed versions as 2.9.7, 2.10.7, 2.11.2, 2.12.1 (all published in 2013). - **Is an affected artifact in `used_components`?** Not evaluated further — dropped at the version-range check (`camel-core`/`camel-file`/`camel-ftp` are used components, but the range check alone already clears 4.8.8).
- **Severity:** GitHub Advisory Database lists this Moderate (EPSS ~8.5%); not re-derived since not affected.
- **Verdict: NOT RELEVANT** (version not affected). This is the same finding already tracked under `CVE-2013-4330` (recorded 2026-07-15, `NOT_RELEVANT`) — only the GHSA id is new, same pattern as `GHSA-hh8r-75r6-qrg9` (2026-09-15) and `GHSA-x9fv...` surfacing later than its CVE.
- **Sources:**
  - https://github.com/advisories/GHSA-x9fv-c87w-55wc

- **Does the affected version range include our pinned version?** `AFFECTED` (by mechanism, not checked further) — `camel-opa` did not exist prior to CAMEL-24634 (new component, merged well after 4.8.8); the finding is moot for our pin regardless of mechanism.
