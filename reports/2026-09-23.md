## Findings

### CAMEL-24691 — camel-saxon: XQueryBuilder XXE via unguarded default Configuration

- **Is this a vulnerability?** `SUSPECTED` — the PR frames it explicitly as a security fix ("aligns XQuery with existing protections in `XmlConverter` and `camel-xslt-saxon`, mirroring CAMEL-24475 for XPath"), but no CVE/GHSA has been assigned.
- **Does the affected version range include our pinned version?** `AFFECTED` (by mechanism) — `XQueryBuilder` only applied space-stripping to its default `ParseOptions` prior to this fix; a `Source`-typed body carrying a `DOCTYPE` declaration would have its external entities resolved. This class of defect (unguarded default XML parsing) has been present since the component's original design, well before 4.8.8 and 4.21.0. Not independently re-verified against the 4.8.8 source (dropped on the component-use check below before spending effort there).
- **Is an affected artifact in `used_components`?** `NOT-USED` — `camel-saxon` (and its `xquery:`/Saxon-XQuery integration) is **not** present in `config/libraries.yaml`'s `used_components` list. Note this is a distinct artifact from `camel-xslt` (which *is* used) — `camel-xslt-saxon` and `camel-saxon` are separate, Saxon-specific components not in our deployed jar list.
- **Severity:** No CVSS published. Estimated **MODERATE** *(estimated)* — classic XXE impact (local file disclosure, SSRF, in some configurations RCE via crafted DTD), but conditioned on an application actually feeding untrusted `Source` bodies into an `xquery:` endpoint or `XQueryBuilder`-based expression, and moot here since the component isn't deployed.
- **Verdict: NOT RELEVANT** (component not used).
- **Sources:**
  - Fix PR: https://github.com/apache/camel/pull/26344 (merged 2026-09-22, `main`; backported to `camel-4.22.x` and `camel-4.18.x` per the PR)
  - Files changed: `components/camel-saxon/src/main/java/org/apache/camel/component/xquery/XQueryBuilder.java`, `components/camel-saxon/src/test/java/org/apache/camel/component/xquery/XQueryXxeTest.java`, `docs/user-manual/modules/ROOT/pages/camel-4x-upgrade-guide-4_23.adoc`
  - Related prior fix referenced: CAMEL-24475 (XPath XXE — already out of our incremental window, not independently checked this run since it doesn't affect a used component either)
  - No CVE/GHSA/NVD record found for this ticket as of this run.
- No backport assessment performed (NOT RELEVANT, not high-severity NEEDS REVIEW).

- **Does the affected version range include our pinned version?** `UNCLEAR`/not assessed in detail — dropped at the component-use check below. (For reference: the defect is in the `camel-debezium-maven-plugin` catalog generator, affecting the six generated Debezium connectors' metadata; not a runtime code-path issue.)

- **Verdict: NOT RELEVANT** (component not used).
