## Findings

None of today's new fingerprints cross the `AFFECTS_US` or `NEEDS_REVIEW` bar. Two are recorded
here rather than in "ruled out" because they touch a **used** component or a genuinely
security-adjacent code path:

### CAMEL-23994 — camel-kafka: `SeekUtil`/`KafkaResumeAdapter` seek and resume-offset bugs

- **Is this a vulnerability?** NOT-SECURITY. Two commits under the same Jira ticket:
  - `d160a2edcd14faa5045d8ba687bc5a9f7403e98d` — `pollOnError` previously called
    `SeekUtil.seekToNextOffset` with a hardcoded offset of `-1`, seeking `position+1` on *all*
    assigned partitions on any poll-loop exception, silently dropping one unread message per
    unrelated partition. Now only the partition tied to a `RecordDeserializationException`
    (poison message) is seeked past the failing offset; other exception types leave positions
    untouched.
  - `7e0d5555f50c8a9a6377eb8fe4c2f672a58b0c34` — an inverted key-format check in
    `KafkaResumeAdapter.deserialize()` discarded valid 2-part topic/partition keys and instead
    tried to parse invalid ones, throwing `ArrayIndexOutOfBoundsException` and preventing
    `resumeStrategy`-configured consumers from ever restoring persisted offsets on restart.
  - Both are data-loss / reliability bugs (CWE-class: none — no injection, disclosure, auth, or
    resource-exhaustion vector; failure requires no attacker-controlled input beyond ordinary
    consumer operation), not a CVE/GHSA-worthy vulnerability. No CVE/GHSA assigned.
- **Affected range vs. our version?** Would be AFFECTED — the bugs exist in code paths present
  since well before 4.8.8 (`SeekUtil`, `KafkaResumeAdapter`).
- **Component in use?** **USED** — `camel-kafka` is in `used_components`. Flagged here (rather
  than silently dropped) because the component is in use and the bugs are real, even though they
  don't meet this watch's security bar. Worth an optional non-security backport for reliability
  if a `resumeStrategy` or `pollOnError` recovery is relied on in production.
- **Source:** commits `d160a2edcd14` (closes apache/camel#24687) and `7e0d5555f50c` (closes
  apache/camel#24684) on `apache/camel` `main` (2026-07-14). `main`-only; not on `camel-4.8.x`.

### CAMEL-22538 — camel-pqc: Azure Key Vault Lifecycle Manager (new feature, not a fix)

- **Is this a vulnerability?** NOT-SECURITY — this is a new feature (`AzureKeyVaultKeyLifecycleManager`),
  not a fix. It stores post-quantum private/public keys and metadata as three separate Azure Key
  Vault secrets rather than as one blob, specifically so different access policies can be applied
  to each — a defensive design choice, not a vulnerability remediation. Flagged here only because
  a naive keyword match on "secret" could otherwise be mistaken for a security fix.
- **Affected range vs. our version?** N/A — new capability, no bug being fixed.
- **Component in use?** **NOT USED** — `camel-pqc` is not in `used_components`.
- **Source:** commit `2c57c0c1d2b4154841394e5f866e4f2cb8475f49` on `apache/camel` `main`
  (2026-07-21), PR https://github.com/apache/camel/pull/24953.
