## Findings

### CVE-2026-25747 — Camel-LevelDB deserialization of untrusted data

- **Is this a vulnerability?** `CONFIRMED` — published Apache Camel security advisory, CWE-502.
- **Description:** `DefaultLevelDBSerializer` in `camel-leveldb` deserializes objects read back from the LevelDB-backed aggregation repository using plain `java.io.ObjectInputStream`, with no `ObjectInputFilter` or class-loading restriction. An attacker able to write to the LevelDB database files used by the application can plant a crafted serialized object that executes arbitrary code when the aggregation repository next reads it.
- **Affected range:** `org.apache.camel:camel-leveldb` 4.10.0 – before 4.10.9, 4.14.0 – before 4.14.5, 4.15.0 – before 4.18.0. Fixed in **4.18.0** (4.10.9 / 4.14.5 for the LTS streams). Our pinned **4.8.8** predates every stated affected range (the component existed in 4.8.8 too, but the advisory's lower bound starts at 4.10.0 — unlike the `CVE-2026-66906` case corrected in the previous run, we did not find independent evidence the pre-4.10 code shares the exact unguarded pattern, and did not deep-dive it further given the component isn't in use — see below).
- **Component analysis:** `camel-leveldb` is **not** present in `config/libraries.yaml`'s `used_components` list → **NOT-USED**. This alone settles the verdict regardless of the affected-range question above.
- **Verdict: NOT RELEVANT.**
- **Sources:** [official advisory](https://camel.apache.org/security/CVE-2026-25747.html) (found live via WebSearch snippet; direct fetch still blocked, see Source health) · [oss-sec mailing list post](https://seclists.org/oss-sec/2026/q1/180) · [`announce@apache.org` archive copy](http://www.mail-archive.com/announce@apache.org/msg10749.html) · [Tenable](https://www.tenable.com/cve/CVE-2026-25747) · [Snyk](https://security.snyk.io/vuln/SNYK-JAVA-ORGAPACHECAMEL-15353482) · fix ticket family: [`CAMEL-22966`](https://issues.apache.org/jira/browse/CAMEL-22966).
- **Note:** this CVE's own oss-sec announcement is dated Q1 2026 (well before our monitoring window) — it surfaced only now via a general WebSearch security-advisory sweep, not via the `apache/camel` commit log (the fix long predates our lookback). It is treated as new for this run because its fingerprint was not previously in `state/seen.json`; a companion advisory published in the same batch, `CVE-2026-23552`, was already recorded from an earlier run.

### CAMEL-24578 — Avro `ClassSecurityValidator` runtime configuration (security-adjacent, no CVE)

- **Is this a vulnerability?** `SUSPECTED` — not itself a new vulnerability; it is a compatibility fix that wires up a *new upstream Avro security control* (Avro 1.12.2's `ClassSecurityValidator`, which gates IPC handshake / application-model class deserialization behind a `SERIALIZABLE_PACKAGES` allowlist) so `camel-avro`/`camel-avro-rpc` keep working after the Avro dependency bump, by auto-deriving trusted packages from the protocol/schema classes at runtime. Flagged because it touches deserialization-adjacent trust configuration, the same risk class as several confirmed Camel CVEs this watch has tracked (e.g. `allowTemplateFromHeader`-style controls).
- **Affected range / our version:** n/a — no vulnerability is being patched; it's new Avro-version support. Camel 4.8.8 does not carry Avro 1.12.2 or the `ClassSecurityValidator` mechanism.
- **Component analysis:** neither `camel-avro` nor `camel-avro-rpc` appears in `used_components` → **NOT-USED**.
- **Verdict: NOT RELEVANT.**
- **Source:** [`d5160fd41ba67df212cdf8840f8e5b2aa611303a`](https://github.com/apache/camel/commit/d5160fd41ba67df212cdf8840f8e5b2aa611303a) (`CAMEL-24578`).
