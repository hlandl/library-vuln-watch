## Findings

All 7 new fingerprints in the window were read in full (`git show`) and assessed:

- **CAMEL-23376** — build tooling only (`maven-release-plugin`/`camel-package-maven-plugin`): adds a `completionGoals` step to regenerate `src/generated/` after a release so the just-released version is embedded correctly, avoiding a manual "refresh PR". `NOT-SECURITY`; affects the project's own release process, not a runtime artifact. [apache/camel@317d36789](https://github.com/apache/camel/commit/317d36789179dfd3aad9332bf3bbca5673913732).
- **CAMEL-23825** — build tooling only (`camel-package-maven-plugin`): fixes a spurious `WARN` + stack trace logged when `jandex.idx` is simply absent (an expected condition for several modules), demoting it to a debug-level, no-stack-trace log. `NOT-SECURITY`. [apache/camel@db0e4452d](https://github.com/apache/camel/commit/db0e4452d82bef9f1c10498032cab4b52763ccc1).
- **CAMEL-24216** — `camel-xslt`: wraps the `setAttribute` call for `jdk.xml.xpathTotalOpLimit` in a try-catch (matching the existing behaviour in `XsltSaxonEndpoint`), so a custom `transformerFactoryClass` that doesn't support that JDK-specific attribute no longer fails route startup with `IllegalArgumentException`. Pure startup-robustness fix, `NOT-SECURITY` (does not loosen or remove the XXE/entity-resolution hardening already in place — it only prevents a benign attribute-setting call from throwing). `camel-xslt` **is** a `used_component`, but this is not a vulnerability or a weakening of one. [apache/camel@31906889d](https://github.com/apache/camel/commit/31906889dadef0e8dbe30d014b36e02abc98cdd9) (PR [#26331](https://github.com/apache/camel/pull/26331)).
- **CAMEL-24676** — `camel-jgroups`: the consumer maps an incoming cluster message to the exchange body via `org.jgroups.Message.getObject()`, which Java-deserializes the payload; this had no `ObjectInputFilter` constraint. A new `deserializationFilter` option (defaulting to the JVM-wide `jdk.serialFilter` if set, else Camel's shared default allow-list) now gates the deserialization, matching the hardening already applied to other Camel components with Java-deserialization surfaces (e.g. the JMS/Hazelcast/Infinispan/Consul CVEs already on file). This **is** a genuine security-relevant hardening change — assessed `SUSPECTED` (no CVE/GHSA assigned yet). However `camel-jgroups` is **not** in `used_components` → **NOT RELEVANT** (component not used). Severity if in scope: *(estimated)* HIGH (unauthenticated Java deserialization RCE surface, same class as the JMS/Hazelcast findings already tracked). [apache/camel@0ef94ee8f](https://github.com/apache/camel/commit/0ef94ee8feabf56a5c595c07b2c60f64a73ba14e) (PR [#26267](https://github.com/apache/camel/pull/26267)).
- **CAMEL-24680** — `camel-jpa` (test-only entity mapping, `@since 4.23`, unreleased): moves `KeyValueEntry` from property access to field access for consistency with sibling test entities. `NOT-SECURITY`; `camel-jpa` is not a `used_component`, and the change is confined to test fixtures. [apache/camel@d6adc5e0f](https://github.com/apache/camel/commit/d6adc5e0f83a637223cc25d9a05c9221c736db47) (PR [#26280](https://github.com/apache/camel/pull/26280)).
- **CAMEL-24681** — `camel-jbang`: `camel export` now also reads Maven repository URLs from the `camel.jbang.repos`/`camel.extra.repos` properties into the generated `pom.xml`. Feature/tooling addition, `NOT-SECURITY`; `camel-jbang` is not a `used_component`. [apache/camel@2dd4c7826](https://github.com/apache/camel/commit/2dd4c7826ed88ac0ce3c11de0453b21c82491c33).
- **CAMEL-24687** — `camel-quickjs`: under sustained load, each QuickJS engine instance grows by ~12 KB per module evaluation and was never recycled, causing an `OutOfMemoryError` after enough invocations (an 8-thread load test filled a 1 GB heap in 22 seconds). A worker's engine is now closed and recreated once it exceeds a configurable memory (`engineMaxMemory`, default 64 MB) or evaluation-count (`engineMaxEvaluations`, default 50,000) threshold. This is a genuine resource-exhaustion/DoS hardening fix — assessed `SUSPECTED` (no CVE assigned; unbounded memory growth under attacker-influenced repeated invocation is a plausible DoS vector). However `camel-quickjs` is **not** in `used_components` → **NOT RELEVANT** (component not used). Severity if in scope: *(estimated)* MEDIUM (availability impact only, requires many repeated invocations). [apache/camel@2efea4730](https://github.com/apache/camel/commit/2efea47304e1e7f485a70403927a46c2738cfe1b) (PR [#26308](https://github.com/apache/camel/pull/26308)).

**Verdict for all 7 new fingerprints above: NOT RELEVANT.**
