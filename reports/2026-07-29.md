### CAMEL-24281 — camel-platform-http-main: JWT authenticator did not fail closed with no issuer/audience configured

- **Is this a vulnerability?** SUSPECTED — no CVE/GHSA assigned as of this run. Real
  security-hardening fix: previously, if neither `jwtIssuer` nor `jwtAudience` was configured,
  `buildJwtOptions` returned `null` and the caller silently skipped `setJWTOptions`, so tokens
  were checked for signature and expiry only — `iss`/`aud` claims were never validated, with no
  warning to the operator. The fix makes the embedded server and management server **fail to
  start** in that misconfiguration instead.
- **Affected range vs. our version?** Would be AFFECTED if the component were present — pinned
  4.8.8 predates this component's JWT-issuer/audience-required options entirely.
- **Component in use?** **NOT USED** — the vulnerable behavior lives in
  `components/camel-platform-http-main` (`JWTAuthenticationConfigurer.java`), which is **not** in
  `used_components`. The commit also touches two configuration-property classes in
  `core/camel-main` (`HttpServerConfigurationProperties.java`,
  `HttpManagementServerConfigurationProperties.java`) — `camel-main` *is* in `used_components`,
  but these classes are inert option carriers for the platform-http-main server; without that
  component on the classpath there is no embedded HTTP server or JWT authenticator for them to
  configure. Verdict: NOT RELEVANT, but flagged here rather than silently dropped because
  `camel-main` is a used component and this is an auth-bypass class of bug — worth a second human
  look if `camel-platform-http-main` is ever added to the used-components list.
- **Source:** commit `4dbb9387102c102ab207e61c8307a3eaaeec7fcf` on `apache/camel` `main`
  (2026-07-28), PR https://github.com/apache/camel/pull/25187. `main`-only; not on `camel-4.8.x`.

### CAMEL-24146 — core/camel-support: `FluentProducerTemplate` leak in `InMemorySagaCoordinator`

- **Is this a vulnerability?** NOT-SECURITY — every saga-step invocation previously called
  `camelContext.createFluentProducerTemplate()` and never stopped the result, so
  `ProducerTemplate` instances (and their internal producer caches/threads) accumulated for the
  lifetime of the context. Fixed by reusing one long-lived `ProducerTemplate` per
  `InMemorySagaService`, started/stopped with the service. This is a resource leak / gradual
  degradation bug (relevant to long-running processes with many saga invocations), not an
  injection, disclosure, or auth issue — no CWE class beyond CWE-772 (missing release of
  resource), and it requires no attacker input beyond ordinary saga usage to trigger.
- **Component in use?** USED — the affected code is in `core/camel-support`
  (`org.apache.camel.saga.InMemorySagaCoordinator`/`InMemorySagaService`), and `camel-support` is
  in `used_components`. Recorded as NOT RELEVANT on the "is this a vulnerability" gate, not the
  component gate — noted here since it's a real, in-scope bug fix worth optionally backporting
  for stability even though it isn't a security finding for this watch's purposes.
- **Source:** commit `4b9ece08c9dd8945648c772bb4c57aa47e5a3af8` on `apache/camel` `main`
  (2026-07-17), no PR number in the commit trailer. `main`-only; not on `camel-4.8.x`.
